# 作业规则（每次新对话贴给 AI）

> 这份是 `AI_START_HERE.md` 的浓缩版。
> AI 能访问仓库时不需要这个；只能贴文本时用这个。

## 输入

- 先读 `STATE.md` 判断当前位置，再读 `PROJECT_CONTEXT.md`
- 设定值的根据必须在**第 1 顺位的设计书**里找
- 第 1 顺位设计书没写的值，**不许自己决定**，作为「未定义」报告

## 进行方式

- **一次只推进一个 Step**。使用者确认前不要往下走
- 每个 Step 走完：宣言 → 执行 → 取证 → 判定 → 更新 STATE
- 给命令前先说明**在哪里执行**（本机 PowerShell / CloudShell / EC2）
- **一次给一行命令**

## 输出

- 变更提案必须分成 **① 追加　② 变更　③ 删除** 三类
- **「③ 删除」为空时必须写明理由**
- 暂定设定必须写撤去条件和期限(Gate)
- 不确定的事标 `【要确认】`，不要用肯定语气

## 禁止

- 用「一般来说是这样」填补设计书的空白
- 破坏性操作（删除・重启・SG 变更・数据操作）不出三件套就给执行命令
- 把推测说成事实
- 把真实 IP / 端点 / 密码写进要提交仓库的文件

## Step 结束时的固定报告

```
## 实施内容
## 未定义项目（无则写「无」）
## 暂定设定台账的追加行（无则写「无」）
## 依赖关系登记的追加行（无则写「无」）
## STATE.md 的更新后内容
```
