# P-80　最终审计（CloudShell）

> **目的**：在交付 / Gate 之前，机械地找出「和设计不符的地方」。
> 人的目视和记忆会漏，脚本不会。

---

## 何时执行

| 时机 | 目的 |
|---|---|
| **每个 Gate**（特别是 G5 / G6 / G8） | 撤去漏れ・设定漏れ的检出 |
| **IT 开始前** | 调试用设定的残留检出 |
| **交付前** | 最终确认 |
| 每周一次 | 悄悄增加的设定的检出 |
| **上位者指摘之后** | 同类问题是否还有别的 |

---

## 脚本做两件事

| | 内容 | 判定者 |
|---|---|---|
| **第 1 部** | 不需要设计书就能判定的项目 → `PASS` / `WARN` / `FAIL` | **脚本** |
| **第 2 部** | 必须对照设计书才能判定的项目 → 输出数据 | **AI**（Prompt A-11） |

---

## 执行步骤

### Step 1　在 CloudShell 执行

> 场所：**AWS CloudShell**（区域要和目标环境一致）

```
git clone <本仓库URL> && cd <仓库名>
```

```
bash scripts/audit.sh | tee ~/audit-$(date +%Y%m%d).txt
```

区域不同时：

```
AWS_REGION=<REGION> bash scripts/audit.sh | tee ~/audit-$(date +%Y%m%d).txt
```

> 需要 `jq`。CloudShell 默认已装。

### Step 2　下载报告

CloudShell 右上 **Actions** → **Download file** → 输入 `audit-YYYYMMDD.txt`

### Step 3　处理第 1 部的 FAIL / WARN

| 判定 | 处理 |
|---|---|
| **FAIL** | **几乎确定是问题。** 按「方案・影响・复旧」三件套处理 |
| **WARN** | 对照 `workspace/TEMP_SETTINGS.md`。**台账里没有 = 没有任何人负责撤去 = 按 FAIL 处理** |
| PASS | 无需处理 |

### Step 4　第 2 部交给 AI 对照设计书

用 `docs/92-prompts.md` 的 **A-11** 模板。

### Step 5　记录

结果填进 `workspace/GATE_LOG.md` 或 `workspace/AUDIT_LOG.md`。

## 第 1 部　检查项目一览

### 1. 安全组

| 检查 | 判定 | 为什么 |
|---|---|---|
| SSH(22) 开放 `0.0.0.0/0` | **FAIL** | 暴力破解的对象。应限定运维终端 IP 或改用 SSM |
| ELB 以外的 SG 开放 HTTP/HTTPS 给 `0.0.0.0/0` | **FAIL** | **可以绕过 ALB 直接访问 EC2 → 闭局无效** |
| DB 端口开放 `0.0.0.0/0` | **FAIL** | DB 不应从互联网可达 |

### 2. 负载均衡器・监听器

| 检查 | 判定 | 为什么 |
|---|---|---|
| HTTPS 已配置，但 HTTP:80 监听器还在 | **FAIL** | SSL 化后 80 应删（重定向用途时 PASS） |
| 没有 HTTPS 监听器 | WARN | SSL 化前是正常的 |
| HTTP:80 是重定向到 HTTPS | PASS | |

### 3. 开闭局处理的参照先

| 检查 | 判定 | 为什么 |
|---|---|---|
| Lambda 的环境变量指向**已删除的监听器** | **FAIL** | **开闭局静默失效，而且不报错** |
| 指向 HTTP 监听器但已 HTTPS 化 | WARN | 要改成 HTTPS 的 ARN |

> **这一项是最容易漏、后果最严重的。**
> 删 HTTP 监听器之前必须先改 Lambda 的 ARN 并实测。

### 4. RDS

| 检查 | 判定 |
|---|---|
| `PubliclyAccessible = true` | **FAIL** |
| `BackupRetentionPeriod = 0` | **FAIL** |
| **保留期有设定但自动快照 0 件** | **FAIL** |
| 存储未加密 | WARN |
| Multi-AZ 无效 | WARN（对照设计要求） |

> 「保留期有设定但快照 0 件」= **备份窗口落在停机时间带**。
> 设定看起来完美，实际一次都没执行过，而且**不会有任何错误提示**。

### 5. 监视・通知

| 检查 | 判定 | 为什么 |
|---|---|---|
| **SNS 有未承认的订阅** | **FAIL** | **告警变 ALARM 但邮件不会到** |
| 告警没有通知动作 | **FAIL** | 发报了也没人知道 |
| SNS 订阅者 0 件 | WARN | |
| SNS 订阅者仅 1 名 | WARN | 担当者不在时无法察觉 |
| 告警 0 件 | WARN | |

### 6. 调度

| 检查 | 判定 | 为什么 |
|---|---|---|
| **EndDate 已过** | **FAIL** | **已经不会发火了** |
| State ≠ ENABLED | WARN | |
| cron 指定了月份 | WARN | **下个月起完全不发火** |

### 7. 无谓的课金

| 检查 | 判定 |
|---|---|
| 未附加的 Elastic IP | WARN |
| 未附加的 EBS 卷 | WARN |
| NAT 网关运行中 | WARN |

### 8. 证书

| 检查 | 判定 |
|---|---|
| Status ≠ ISSUED | **FAIL** |
| 有效期限 < 30 天 | **FAIL** |
| `InUseBy` 为空（没绑到任何资源） | WARN |

### 9. 目标的健全性

| 检查 | 判定 |
|---|---|
| 有非 healthy 的目标 | WARN（变更直后是正常的，等满时间常数再看） |

### 10. CloudFormation

| 检查 | 判定 |
|---|---|
| `DRIFTED` | WARN（确认是否已记入差分一览） |
| `IN_SYNC` | PASS（**但要确认是变更之后取的**） |
| 未检出 | WARN（跑 `detect-stack-drift`） |

## 第 2 部　输出的数据

AI 用这些和设计书对照：

| 记号 | 内容 | 对照对象 |
|---|---|---|
| A | 监听器构成 | 最终状态定义书 1.1 |
| B | 安全组入站全件 | 最终状态定义书 1.2 |
| C | 目标组・健康检查 | 最终状态定义书 1.3 |
| D | EC2 | 最终状态定义书 1.4 |
| E | RDS | 最终状态定义书 1.5 |
| F | 调度（cron 是 UTC） | 方式设计书的运用调度 |
| G | 告警 | 方式设计书的监视方针 |
| H | Lambda 环境变量 | 开闭局的对象 ARN |

## 脚本检不出来的东西（必须人做）

脚本只能看 AWS API 能返回的东西。以下**必须人去确认**：

| # | 项目 | 确认方法 |
|---|---|---|
| 1 | **闭局是否真的遮断** | 闭局时间带 `curl` 3 个入口（HTTPS / HTTP / EC2 直接） |
| 2 | **监视是否真的发火** | 人为制造事件，看 `MatchedEvents` / `Invocations` / `FailedInvocations` / 目标记录 |
| 3 | **告警邮件是否真的到达** | 临时下调阈值，确认收到邮件 |
| 4 | EC2 内部的配置 | SSH 进去看 httpd / Tomcat 的配置文件 |
| 5 | `webapps/` 下有无多余目录 | `sudo ls -l <CATALINA>/webapps` |
| 6 | 管理应用是否被遮断 | 访问 `/manager/html` `/docs/` 确认 404 |
| 7 | 应用的行为 | 实际操作画面 |
| 8 | 文档里的 `http://` 残留 | 全文检索 |

> **1・2・3 是「设定看起来完美但实际不工作」的三大代表。**
> AWS API 返回的都是正常值，只有实测才能发现。

## 结果的读法

```
PASS : 25
WARN : 4
FAIL : 2
```

| 情况 | 处理 |
|---|---|
| FAIL ≥ 1 | **几乎确定要是正。** 逐条出三件套处理 |
| FAIL = 0, WARN ≥ 1 | 对照 `TEMP_SETTINGS.md`。**台账里没有的 WARN 按 FAIL 处理** |
| 全 PASS | 机械判定范围内无问题。进第 2 部的设计书对照 |

## 追加检查项目

项目固有的检查项，追加到脚本的第 1 部。格式：

```bash
# ---------- N. <分类> ----------
echo; echo "■ N. <分类>"

<取值的命令> > /tmp/_aN
if <条件>; then
  fail "<为什么是问题，用使用者看得懂的话>"
else
  pass "<确认了什么>"
fi
```

> **写 `fail` 的信息时，要写「为什么是问题」，不要只写「不符合」。**
> 半年后的自己看不懂「不符合」是什么意思。
