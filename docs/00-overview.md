## Gate 一览

Gate = 状态迁移的节点。**每个 Gate 都有「撤去清单」。**

| Gate | 触发条件 | 核心撤去项 |
|---|---|---|
| **G1** | 环境设计书写完 | （检查而非撤去）文档间一致性 |
| **G2** | 同上 | （检查）设计的实在性 |
| **G3** | 栈构筑完成 | （检查）实环境 vs 设计书 |
| **G4** | 域名取得・DNS 设定完了 | 临时 URL 的使用停止 |
| **G5** | **证书取得・HTTPS 化完了** | **HTTP:80 监听器 / ELB SG 的 80 / EC2 SG 的 0.0.0.0/0** |
| **G6** | 构筑完了 → IT 开始 | 调试用开放 / 临时内容 |
| **G7** | IT 完了 → UAT | 测试数据 / 暂定设定全撤 |
| **G8** | UAT 完了 → 交付 | 历史数据 / 文档最终化 |

**每个 Gate 都要先跑 `scripts/audit.sh`**（→ `docs/93-audit.md`）。
脚本给出 `PASS` / `WARN` / `FAIL`，人再对照清单逐项判定。

## 四类事故与对策

| # | 事故 | 机制 | 位置 |
|---|---|---|---|
| A | 两份设计书矛盾，抄了错的那份 | **G1 一致性检查** | Phase 1 |
| B | 改了 A，依赖 A 的没人查 | **依赖关系登记** | Phase 1 / 4 |
| C | 设计书本身写错了 | **G2 实在性审查** | Phase 1 |
| D | 加了新的，旧的没删 | **最终状态定义 + Gate** | Phase 1 / 3 |

## 文档优先顺位（最重要的一条规则）

| 顺位 | 文档 | 定义什么 |
|---|---|---|
| **1** | 方式设计书 | What / Why。非功能要求・安全方针・最终状态 |
| **2** | 环境设计书 | How / 参数。具体设定值 |
| **3** | IaC 模板 | 实装 |
| **4** | 运用手顺书 | 操作 |

> **铁则：下位文档的每一个值，都必须能追溯到上位文档的某一行。**
> **追溯不到 = 未定义 = 回到上位确认，不许自己填。**

模板文档（研修・公司提供）带着样例值。项目开始时**全部标记为「未确认」**，
逐条对照方式设计书确认后才能用。**「未确认」的值一个都不许进 IaC。**

## 时间常数

| 操作 | 判定前必须等 |
|---|---|
| 安全组规则变更 | 0 秒 |
| 目标组变 Healthy | 间隔 × Healthy 阈值（典型 150 秒） |
| 目标组变 Unhealthy | 间隔 × Unhealthy 阈值（典型 60 秒） |
| RDS 停止 → 启动 | 约 20 分 |
| RDS 重启 | 3〜5 分 |
| Tomcat 重启 | 20〜30 秒 + 恢复 150 秒 |
| ALB 空闲超时 | 60 秒 |

**实际值在 Phase 0 填进 `workspace/PROJECT_CONTEXT.md`。**
