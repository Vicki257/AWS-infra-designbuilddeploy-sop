## A-1　文档间一致性检查（G1）

```
以下の2つの設計書の記載内容を突き合わせ、矛盾を検出してください。

【第1順位】<方式設計書など>
<内容を貼る。Excelならシート名ごとにテキストで貼る>

【第2順位】<環境設計書など>
<内容を貼る>

---

## 出力形式

| # | 項目 | 第1順位の記載 | 第2順位の記載 | 判定 |
|---|---|---|---|---|

判定は次の3つから選んでください。
 ・矛盾（両者が異なる値を定義している）
 ・欠落（第1順位にあるが第2順位にない）
 ・過剰（第2順位にあるが第1順位に根拠がない）

## 特に重点的に突き合わせる項目

 - セキュリティグループの全ルール（種別・ポート・ソース）
 - ロードバランサーのリスナー構成（プロトコル・ポート）
 - ミドルウェアのバージョン
 - ヘルスチェックのパスとプロトコル
 - 稼働スケジュールと各種ウィンドウ（バックアップ・メンテナンス）
 - 暗号化の有無
 - 冗長構成（Multi-AZ 等）
 - 公開URL・パス

## 注意

 - 「一般的にはこうです」という補足は不要です。両文書の記載のみで判定してください。
 - 第2順位の文書がテンプレート由来のサンプル値を含んでいる可能性があります。
   第1順位に根拠のない値はすべて「過剰」として報告してください。
 - 判定に迷うものは【要確認】として、断定しないでください。
```

## A-2　设计实在性审查（G2）

```
以下の設計書を、実在性・整合性の観点でレビューしてください。

<設計書の内容を貼る>

---

## 観点

1. 実在しない値
   - ソフトウェアのバージョンが実在するか
   - AWSのインスタンスタイプ・エンジンバージョンが実在するか
   - 指定リージョンで利用可能か

2. 組み合わせの妥当性
   - ミドルウェア間のバージョン互換性
   - OSとミドルウェアの対応
   - AWSサービス間の制約

3. 数値の整合性
   - 時刻・スケジュールに矛盾がないか
   - 容量・閾値が現実的か

4. 記載の欠落
   - 本番運用に必要だが記載がない項目

## 出力形式

| # | 箇所 | 記載内容 | 指摘 | 根拠 | 重要度 |
|---|---|---|---|---|---|

重要度は 高 / 中 / 低。
確信が持てないものは【要確認】として、断定しないでください。
```

## A-3　依赖关系抽出

```
以下の設計書から、設定値の依存関係を抽出してください。

<設計書の内容を貼る>

「ある値を変更したとき、連動して見直しが必要になる値」の組を列挙してください。

## 出力形式

| # | 変更する値 | 影響を受ける値 | 理由 |
|---|---|---|---|

## 最低限、以下の依存が含まれているか確認してください

 - 稼働スケジュール → バックアップウィンドウ
 - 稼働スケジュール → メンテナンスウィンドウ
 - 稼働スケジュール → 監視アラームの欠損データ扱い
 - 証明書の取得 → リスナー構成
 - 証明書の取得 → セキュリティグループのインバウンド
 - 証明書の取得 → 開閉局処理の対象ARN
 - 公開パス → ヘルスチェックパス
 - 公開パス → リバースプロキシ設定
 - 公開パス → Outputs のURL
 - インスタンスタイプ → コスト試算

該当しないものは「該当なし」と明記してください。
```

## A-4　IaC 模板生成

```
以下の設計書に基づいて CloudFormation テンプレートを作成してください。

【環境設計書（確定版）】
<内容を貼る>

【最終状態定義書】
<内容を貼る>

【現在のフェーズ】
<P1疎通確認 / P2 / 最終状態>

---

## 作成ルール

1. 各リソースに、設計書のどの項目に対応するかをコメントで明記すること
   例： # 環境設計書 1.ネットワーク設計 4.セキュリティグループ No.1

2. 設計書に記載のない値は勝手に決めないこと
   必要だが記載がない場合、テンプレートに含めず「未定義項目」としてリストアップすること

3. 最終状態定義書の「（上記以外は存在しないこと）」を満たすこと
   余分なリソース・ルールを作らないこと

4. 暫定的に必要な設定がある場合
   ・テンプレート内に `# 暫定：<理由> / 撤去条件：<条件> / 期限：<Gate>` とコメント
   ・作業終了時に暫定設定台帳の行として出力すること

5. リソースの再作成を招く書き方を避けること
   ・AMI ID は固定値にすること（`{{resolve:ssm:...latest}}` は使わない）
   ・UserData の変更は EC2 再作成を招くため、変わりうる設定は外に出すこと

6. スタックを課金有無で分けること
   ・無課金（VPC/サブネット/ルートテーブル/SG/キーペア）
   ・課金あり（EC2/RDS/ALB/証明書/DNS）
   ・運用（Lambda/スケジュール/アラーム）

## 出力

 1. テンプレート本体
 2. 未定義項目リスト
 3. 暫定設定台帳への追加行
 4. このテンプレートでは作られないが、最終状態定義書に書かれているもの
    （＝別途手動作業が必要なもの）
```

## A-5　追溯性检查

```
以下のテンプレートについて、追跡可能性を検証してください。

【テンプレート】
<貼る>

【環境設計書】
<貼る>

## 出力形式

| リソース/プロパティ | 設定値 | 設計書の根拠箇所 | 判定 |
|---|---|---|---|

判定：
 ・OK（設計書に明記あり）
 ・推測（設計書に明記なし、あなたが補完した）
 ・不明（根拠が見つからない）

最後に「推測」「不明」の行だけを抜き出して一覧してください。
この一覧が、使用者が確認すべき項目です。
```

## A-6　构筑后 Reconcile（G3）

```
設計書と実環境を突き合わせ、差分を検出してください。

【最終状態定義書】
<貼る>

【実環境】
<inventory.sh の出力を貼る>

【現在のフェーズ】
<P1 / P2 / 最終状態>

【暫定設定台帳】
<貼る>

---

## 出力形式

### A. 未実装（設計書にあるが実環境にない）
| # | 項目 | 設計書の記載 | 対応 |

### B. 余分（実環境にあるが設計書に根拠がない）
| # | 項目 | 実環境の値 | 暫定台帳に登録済みか | 判定 |

判定は次から選ぶ：
 ・暫定（台帳登録済み・期限内）
 ・撤去漏れ
 ・暫定（台帳未登録）

### C. 値の相違（両方にあるが値が違う）
| # | 項目 | 設計書 | 実環境 | 判定 |

---

## 注意

B の「暫定（台帳未登録）」は**最も危険**です。
誰も撤去責任を持っていない設定なので、必ず B の先頭に出してください。
```

```
以下のGateチェックリストについて、実環境の状態から各項目の合否を判定してください。

【チェックリスト】
<docs/04-phase3-gates.md の該当Gateの表を貼る>

【実環境】
<inventory.sh の出力、および個別のdescribe結果を貼る>

## 出力形式

| # | 項目 | 期待値 | 実際の値 | 合否 | 不合の場合の対応手順 |

合否が「否」の項目については、
「方案・影響・復旧」の3点セットを作成してください。
判定に必要な情報が不足している場合は、
どのコマンドを実行すればよいかを提示してください。
```

## A-8　变更的波及影响检查

```
以下の変更を行います。

【変更内容】
<変更する値>

【依存関係登記】
<workspace/DEPENDENCIES.md を貼る>

【最終状態定義書】
<関係する部分を貼る>

---

この変更によって、連動して見直しが必要になる設定を全て列挙してください。
依存関係登記に記載がないものでも、影響が考えられるものは指摘してください。

## 出力形式

| # | 見直しが必要な設定 | 理由 | 確認方法（コマンド） |

その上で、変更全体について
 ① 追加　② 変更　③ 削除
の3分類で必要な作業を列挙してください。
「③ 削除」が空の場合は、なぜ空でよいのか根拠を述べてください。
```

## A-9　暂定台账的检查

```
【暫定設定台帳】
<workspace/TEMP_SETTINGS.md を貼る>

【現在のフェーズ / 直近のGate】
<現在の状態>

【実環境】
<inventory.sh の出力を貼る>

---

以下を判定してください。

 1. 期限を過ぎているのに撤去されていない行
 2. 撤去済みと記載されているが、実環境にまだ残っている行
 3. 実環境にあるが台帳に無い設定（= 誰も撤去責任を持っていない設定）

3 が最も危険です。先頭に出してください。

## 出力形式

| # | 設定内容 | 分類(1/2/3) | 期限 | 対応 |
```

## A-11　构成审计结果的对照

```
構成監査の結果を設計書と突き合わせてください。

【監査結果 第2部】
<audit.sh の「第2部」の出力を貼る>

【最終状態定義書】
<workspace/FINAL_STATE.md を貼る>

【方式設計書の該当箇所】
<運用スケジュール・監視方針・セキュリティ方針など>

【暫定設定台帳】
<workspace/TEMP_SETTINGS.md を貼る>

---

## 出力形式

### 1. 突き合わせ結果

| # | 監査項目 | 実環境の値 | 設計書の記載 | 判定 |
|---|---|---|---|---|

判定：
 ・一致
 ・不一致（実環境を是正すべき）
 ・不一致（設計書を更新すべき）
 ・暫定（台帳登録済み・期限内）
 ・**暫定（台帳未登録）** ← 誰も撤去責任を持っていない
 ・設計書に記載なし（要確認）

### 2. 是正が必要な項目

不一致のものについて、それぞれ
「方案・影響・復旧」の3点セットを作成してください。

### 3. スケジュールの交差検証

監査結果 F のスケジュールを現地時間に換算し、以下を判定してください。

| 検査項 | 判定 |
|---|---|
| RDSバックアップウィンドウ ⊂ RDS稼働時間 | |
| RDSメンテナンスウィンドウ ⊂ RDS稼働時間 | |
| EC2起動時刻 ≤ 開局時刻 | |
| 閉局時刻 ≤ EC2停止時刻 | |
| cronの月指定・EndDateが発火停止を招かないか | |

---

## 注意

 - 「暫定（台帳未登録）」を最優先で報告してください。
 - 設計書に記載がない項目を「一般的には問題ない」と判断しないでください。
   必ず【要確認】として使用者に返してください。
