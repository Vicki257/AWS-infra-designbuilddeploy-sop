## 变更作业的通用流程

**任何变更都走这 7 步。**

```
① 查依赖关系登记（workspace/DEPENDENCIES.md）→ 列出会被波及的值
② 写「方案・影响・复旧」三件套
③ 记录现状（截图 / 命令输出）
④ 变更（一次只改一处）
⑤ 等满时间常数 → 验证
⑥ 波及的值也变更・确认
⑦ 更新 DIFF_LOG.md / TEMP_SETTINGS.md
```

### ① 的做法

AI 使用 `docs/92-prompts.md` 的 **A-8** 模板。

**这一步跳过的后果**：改了运行时间，备份窗口没跟着改，
备份从此一次都不执行，而且**不会有任何错误提示**。

### ② 三件套的格式

```
## 方案
- 对象资源 / 变更的设定 / 变更前的值 / 变更后的值 / 执行手段

## 影响
- 停止的功能 / 受影响的人 / 影响时间 / 和正常状态的区分方法

## 复旧
- 手顺 / 复旧用的设定值 / 所需时间
```

### ③ 现状记录的粒度

| 变更对象 | 记录方法 |
|---|---|
| 安全组 | 入站规则画面的**截图**（规则全部可见） |
| 目标组 | 健康检查设定画面的截图 |
| RDS 参数 | `describe-db-instances` 的输出保存 |
| 文件 | `sudo cp <文件> <文件>.bak.$(date +%Y%m%d)` |
| 数据库 | `90-playbooks.md` P-10 的备份 |

**没有记录就不要变更。** 回滚时靠的就是这个。

### ⑤ 等待时间常数

> ⚠️ **等待期间出现 Unhealthy 是正常的。这期间不要判定失败并回滚。**

具体秒数从 `workspace/PROJECT_CONTEXT.md` 的时间常数表取。

## 监视的健全性验证

> **「设定存在」≠「监视在工作」。人为制造一次事件来证明。**

### 为什么

- 事件模式和实际事件对不上 → 规则永远不匹配
- 目标的权限不足 → `FailedInvocations` 增加，**通知不会到**
- SNS 订阅未承认 → 告警变 ALARM 但**邮件不会到**

以上三种，**从控制台看「设定完成」都是正常的**。

### 手顺

**Step 1**　人为触发监视对象的事件

例（RDS 停止事件的监视）：
1. 调度暂时变更，或手动停止 RDS
2. 等待事件发生

**Step 2**　确认 4 个点

| # | 确认对象 | 期待值 | 确认方法 |
|---|---|---|---|
| 1 | `MatchedEvents` | ≥ 1 | CloudWatch 指标（`AWS/Events`） |
| 2 | `Invocations` | ≥ 1 | 同上 |
| 3 | `FailedInvocations` | **0** | 同上 |
| 4 | 目标侧的记录 | 事件已记录 | 日志组 / SNS 的接收 |

判读：

| 现象 | 原因 |
|---|---|
| 1・2 为 0 | 规则的事件模式和实际事件不一致 |
| 3 ≥ 1 | 目标的权限不足等。**通知不会到** |
| 4 没有 | 目标设定错误 |

**Step 3**　**必须复旧**（调度、RDS 状态）

**Step 4**　记录

```
| 监视对象 | 验证日 | MatchedEvents | Invocations | FailedInvocations | 目标记录 | 判定 |
```

### 告警（CloudWatch Alarm）的验证

同样要实测：
1. 阈值暂时下调，让它发报
2. **确认邮件实际到达**（不是看 ALARM 状态）
3. 阈值复旧

> SNS 的订阅未承认时，告警会变 ALARM 但邮件不会到。
> `aws sns list-subscriptions-by-topic` 的 `SubscriptionArn` 是
> `PendingConfirmation` 就是未承认。

## 暂定设定台账的运用

### 登记规则

> **「今だけこうしておく」（就先这样放着）这个念头一出现，立刻往台账加一行。**

```
| # | 设定内容 | 追加日 | 追加理由 | 撤去条件 | 期限(Gate) | 状态 |
```

### 定期检查

**每周 + 每个 Gate**，AI 使用 `docs/92-prompts.md` 的 **A-9** 模板检查：

1. 过了期限还没撤去的行
2. 台账写着已撤去但实环境还留着的行
3. **实环境有但台账没有的设定**（= 没有任何人负责撤去）

**第 3 项最危险，必须排在最前面。**
